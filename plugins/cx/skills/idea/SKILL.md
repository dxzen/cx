# CX Idea

目标：通过引导、质疑和数据核验，帮助用户把一个初始点子逐步收敛为可验证的商业假设，判断可行性，并输出一个可直接打开的单页 H5 商业画布。

该命令完全独立：

- 不创建或修改 `.cx/`。
- 不调用 CX CLI。
- 不修改项目已有代码或文件。
- 最终只新增一个 HTML 文件；如果目标文件已存在，先询问用户是否覆盖。

## 参数规则

- 如果 `$ARGUMENTS` 非空，把它作为用户的初始点子。
- 如果 `$ARGUMENTS` 为空，只问一个问题：请用户用一两句话描述想验证的点子。
- 默认把最终文件保存为当前目录下的 `idea-<简短英文 slug>.html`。

## 核心原则

1. **证据优先**：不要迎合用户，也不要先下结论。明确区分：
   - `已验证事实`：来自可靠外部来源或用户提供的真实数据。
   - `用户输入`：用户陈述，但尚未被外部证据验证。
   - `估算`：基于公开数据或用户输入推导，必须写出公式和假设。
   - `待验证假设`：目前没有足够证据。
   - `反证`：与点子关键假设冲突的证据。
2. **拿数据说话**：涉及市场、用户、竞品、价格、行业、政策、成本、转化率等可变信息时，使用 WebSearch 和必要的 WebFetch 核验。优先级为官方统计、监管机构、公司官方资料或财报、权威研究，再到可信行业媒体。记录来源 URL 和发布日期；找不到可靠数据时直说，不要编造。
3. **商业闭环**：至少验证谁有问题、问题有多痛、当前替代方案、为什么会付钱、如何触达、收入和成本是否可持续。
4. **行为洞察**：从心理学角度检查真实采用阻力，例如现状偏好、切换成本、信任、隐私顾虑、损失厌恶、社交证明、习惯形成和激励错配。只使用与当前点子直接相关的因素。
5. **避免伪精确**：未知数据不要硬算。可以给区间和敏感性分析，但必须展示假设。不要把 TAM 当成需求证据，也不要把“有人喜欢”当成付费证据。
6. **逐步深入**：每轮最多问 3 个高信息量问题。用户回答后，先总结新增事实、当前最大风险和下一步为什么问，再进入下一轮。

## 执行流程

### 1. 建立最小点子定义

先确认：

- 目标用户是谁，使用场景是什么。
- 用户现在如何解决，最痛的成本是什么。
- 点子提供什么结果，为什么比现有替代方案更值得切换。

如果用户描述过宽，要求收窄到一个最优先细分人群和一个高频或高损失场景。不要一开始写长篇分析。

### 2. 分轮质疑和核验

根据已知信息选择最有价值的问题，不机械照抄清单。优先覆盖：

- **Problem**：发生频率、严重程度、现有 workaround、用户是否已经花钱或花时间解决。
- **Demand**：谁是使用者、谁是付费者、谁能否决采购、付费触发点、可接受价格区间。
- **Alternatives**：直接竞品、间接替代、自建方案、什么都不做的成本。
- **Distribution**：首批 100 个用户从哪里来，获客渠道是否可重复，是否依赖昂贵教育。
- **Economics**：收费方式、客单价、毛利、交付成本、CAC、回本周期、留存或复购条件。
- **Feasibility**：技术、运营、合规、资金、供应链或网络效应门槛。
- **Behavior**：用户为什么会拖延、不信任、拒绝迁移或很快流失。

得到足够具体的用户和场景后，再做 Web 核验。搜索并整理与当前点子最相关的数据：

- 目标用户规模和可触达细分人群。
- 替代方案与真实价格。
- 行业基准、监管约束、趋势或反证。
- 可用于 bottom-up 估算的变量。

每轮简短输出：

```text
已确认：
- ...

当前最大风险：
- ...

下一轮问题：
1. ...
2. ...
3. ...
```

### 3. 建立可证伪模型

信息足够后，形成最小商业模型：

- 使用 bottom-up 方法估算 `TAM / SAM / SOM`。如果数据不足，保留空缺并列出补数路径。
- 列出 unit economics：价格、收入、变动成本、毛利、CAC、回本周期、留存或复购。没有数据的字段标记为 `待验证`。
- 找出 3-5 个最危险假设，按“影响大且不确定性高”排序。
- 为每个危险假设设计最低成本实验，写清方法、样本、周期、通过阈值和失败后的动作。

不要因为市场规模大就判定可行。判定必须同时考虑需求证据、可触达性、经济性和执行约束。

### 4. 给出结论

只使用以下结论之一：

- `继续验证`：值得做低成本实验，但尚不能投入重资源。
- `有条件推进`：已有较强证据，可以做 MVP；必须列出前置条件。
- `调整方向`：核心问题存在，但当前方案、用户或渠道不成立。
- `暂缓`：关键假设已有明显反证，或经济性无法闭环。

必须解释结论依赖哪些证据，哪些仍是未知数。不要把推断写成事实。

### 5. 生成单页 H5 商业画布

完成分析后，调用 `huashu-design` Skill，把已核验的数据、假设、结论、来源和下面的页面结构作为 briefing，要求生成信息密度适中、移动端优先、可直接打开的单页 H5 商业画布。

H5 必须：

- 是一个自包含 HTML 文件，CSS 和 JS 全部 inline，不创建其他资产文件。
- 在手机和桌面浏览器中可读，适合滚动浏览。
- 视觉重点是商业判断和证据，不做营销 Landing Page。
- 使用标签明确区分 `已验证事实`、`用户输入`、`估算`、`待验证假设`、`反证`。
- 对所有数字显示来源或估算公式。
- 对所有外部事实提供可点击来源链接，并显示来源名称、发布日期或抓取日期。
- 不使用虚构数据，不用没有依据的图表装饰。
- 如果 `huashu-design` Skill 不可用，直接生成克制、清晰的单文件 HTML，不要阻塞交付。

页面至少包含：

1. **Idea Snapshot**：一句话点子、目标用户、核心场景、当前结论、关键未知数。
2. **Evidence Board**：最关键的支持证据、反证和数据缺口。
3. **Business Model Canvas**：
   - 客户细分
   - 价值主张
   - 渠道
   - 客户关系
   - 收入来源
   - 关键资源
   - 关键活动
   - 关键合作伙伴
   - 成本结构
4. **Market & Economics**：bottom-up `TAM / SAM / SOM`、定价、unit economics、敏感性分析。
5. **Behavioral Friction**：最相关的采用阻力和对应验证方式。
6. **Risk Register**：按影响和不确定性排序的危险假设。
7. **Validation Plan**：最低成本实验、通过阈值、周期、下一步动作。
8. **Sources & Assumptions**：来源列表、估算公式、仍需补充的数据。

写入 HTML 后，报告：

- 文件路径。
- 当前结论。
- 最优先执行的一个验证实验。
